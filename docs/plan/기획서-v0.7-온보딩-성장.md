## 1. 개편 요약 — 무엇이 왜 바뀌나

현재 초기 설정은 목적(다이어트/훈련)과 레벨(런린이/런친놈)을 한 번씩 탭하면 끝난다. 이 구조의 한계 세 가지가 이번 개편의 출발점이다.

- **수준을 너무 얕게 잡는다.** 두 번의 탭으로는 10km 기록도, 목표 대회도, 달리는 이유도 모른다. 리포트 문장 난이도만 2단계로 갈릴 뿐이다.
- **다이어트 모드가 몸무게 데이터에 기대고 있다.** 스마트 체중계가 없으면 빈 카드가 뜨고, 감량 정체기에는 앱이 부정적 피드백을 주게 된다. 달리는 행동이 아니라 결과 수치를 앱의 중심에 두는 설계였다.
- **다시 열 이유가 부족하다.** 리텐션 축이 "문장의 재미"(§4.11) 하나뿐이다. 누적형 보상 — 성장하는 재미 — 가 없다.

### 변경 전후 한눈에

| 영역 | 현재 (v0.6) | 개편 (v0.7) |
|---|---|---|
| **초기 설정** | 목적·레벨 각 1회 탭 | 카드형 설문 — 유경험 최대 9문항, 무경험 5문항 |
| **수준 구분** | 2단계 (런린이 / 런친놈) | 3단계 (런린이 / **런잘알** / 런친놈) |
| **목적** | 다이어트/훈련 택1 → 리포트 카드 구성 전환 | 설문 문항으로 흡수(최대 2개 선택) → 문장 톤·가이드에 반영 |
| **몸무게** | 다이어트 모드 카드 + bodyMass 권한 | **완전 제거** (§8) |
| **첫 탭** | 리포트 (지표 카드 나열) | 홈 — 새 성장 스테이지 + 브리핑 1~2문장 (§6) |
| **성장 요소** | streak 카드 1개 (다이어트 모드 한정) | XP · 6단계 성장 + 성조 수집 도감, 전 레벨 공통 (§5) |
| **설정 화면** | 목적/레벨/목표/알림/데모/개인정보 7섹션 | 프로필·목표 / 알림 / 앱 정보 3그룹으로 재편 (§7) |

> **UI 공통 원칙** — 전 화면에서 글보다 이미지가 먼저다. 온보딩 카드는 아이콘 + 한 줄 질문 + 큼직한 선택지, 홈은 새 이미지 + 문장 1~2줄이 전부다. 심플하되 촌스럽지 않게 — 비주얼 기준은 시안 v0.4 "스포티 볼드"(웜 크림 + 레드오렌지)를 그대로 따른다.

## 2. 온보딩 설문 — 카드 플로우

첫 실행에서 카드를 한 장씩 넘기며 답한다. 경험을 먼저 묻고, 경험이 없으면 짧은 길로 보낸다. 과거(경험) 질문을 끝낸 뒤 미래(목표·목적) 질문으로 넘어가고, 마지막에 레벨을 발표하며 알을 준다.

### 설계 원칙

- **카드 1장 = 질문 1개.** 큰 아이콘, 한 줄 질문, 큼직한 선택지 버튼. 타이핑은 없다 — 전부 탭.
- **분기형.** 무경험자는 5문항, 유경험자는 최대 9문항 (요구 한도 10문항 이내).
- **답은 전부 로컬 저장.** 서버 없음 원칙 그대로. 원답(`OnboardingAnswers`)을 보존해 재진단에 쓴다.
- **권한 요청은 설문 뒤로.** 현재는 HealthKit 권한 안내가 첫 화면인데, 개편 후에는 설문 → 결과(알 지급) → 권한 요청 순서로 바꾼다. 맥락을 만든 뒤 요청해야 수락률이 오른다. 설문 자체는 자기 신고라 권한이 필요 없다.
- **문구는 런미새 보이스**(기획서 §4.11). 질문도 정중한 위트로 — 아래 표의 문구는 초안이다.

### 질문 흐름 (분기 트리)

```
                   Q1 · 러닝, 해보신 적 있나요?
                    ├──────────────┬──────────────────────────────┐
       "이제 시작해요" → 짧은 길(5문항)          "좀 달려봤어요" → 최대 9문항
                    ↓                              ↓
        Q2a · 평소 활동량                Q2 · 최장 거리
        (걷뛰 프로그램 시작 강도)        (레벨 판정 입력 · Q3 분기)
                    │                              ↓  5km 미만·하프 이상 완주자는 Q3 건너뜀
                    │                  Q3 · 기록 (10km 또는 풀코스)
                    │                  (중급·런친놈 판정)
                    │                              ↓
                    │                  Q4 · 월 마일리지 → Q5 · 주간 빈도 → Q6 · 대회 경험
                    └──────────────┬──────────────┘
                                   ↓ 합류
            Q7 · 목표 거리 → Q8 · 목표 기록(피커) → Q9 · 달리는 이유
                                   ↓
   결과 카드 — 레벨 발표 + 🥚 알 지급 → HealthKit 권한 요청 → 홈
```

### 질문 명세

| 카드 | 질문 (문구 초안) | 선택지 | 이 답이 정하는 것 | 노출 조건 |
|---|---|---|---|---|
| **Q1** | 러닝, 해보신 적 있나요? | 이제 시작해요 / 좀 달려봤어요 | 플로우 분기 | 항상 |
| **Q2a** | 요즘 몸은 좀 움직이고 계세요? | 주로 앉아 지내요 / 걷기는 챙겨 해요 / 다른 운동을 하고 있어요 | 런린이 걷뛰 가이드 시작 강도 | 무경험 |
| **Q2** | 지금까지 가장 멀리 달려본 거리는요? | 5km 미만 / 5~10km / 10km~하프 / 하프~풀 / 풀코스 완주 | 레벨 판정 ① · Q3 분기 | 유경험 |
| **Q3** | (풀 완주자) 풀코스 기록이 어떻게 되세요?<br>(그 외) 10km는 얼마 만에 들어오세요? | 풀: 4시간 30분 이내 / 4:30~5시간 / 5시간 넘게<br>10km: 1시간 이내 / 1시간 조금 넘게 / 재본 적 없어요 | 런친놈 조건 ① / 중급 판정 | Q2가 5km 이상.<br>하프~풀 완주자는 건너뜀 |
| **Q4** | 한 달에 보통 얼마나 달리세요? | 50km 미만 / 50~100km / 100~200km / 200km 이상 | 런친놈 조건 ② | 유경험 |
| **Q5** | 일주일에 몇 번 나가세요? | 한 번 나갈까 말까 / 2~3번 / 4번 이상 | 주간 러닝 목표 초기값 (1·3·4회) — §5 XP 연동 | 유경험 (무경험은 기본 주 2회) |
| **Q6** | 대회는 나가보셨어요? | 나가봤어요 / 접수해 뒀어요 / 아직요 | 대회 탭 안내 · 가이드 톤 | 유경험 |
| **Q7** | 다음 목표는 어떤 거리인가요? | 5K / 10K / 하프 / 풀 / 아직 없어요 | `raceGoal` (기존 키 재사용) · 훈련 가이드 | 공통 |
| **Q8** | 목표 기록도 정해볼까요? | 시:분 휠 피커 + 프리셋 칩 (스킵: "일단 완주부터요") | `raceGoalSec` | Q7에서 거리 선택 시 |
| **Q9** | 달리는 이유, 뭐예요? | 건강·체력 / 체중 관리 / 기록 단축 / 대회 완주 / 스트레스 해소·습관 (최대 2개) | 브리핑·가이드 문장 톤 | 공통 |

> **"체중 관리"를 골라도 몸무게는 추적하지 않는다.** 목적은 문장 톤(꾸준함 중심의 격려)에만 반영한다. 결과 수치(체중)가 아니라 행동(달리기)을 보상하는 것이 §5 성장 시스템의 역할이다.

### 화면 시안 (와이어프레임)

| 화면 | 구성 |
|---|---|
| **질문 카드** | 상단 진행 점 → 아이콘(🏃) → 한 줄 질문("지금까지 가장 멀리 달려본 거리는요?") → 탭 선택지 5개(5km 미만 / 5~10km / 10km~하프 / 하프~풀 / 풀코스 완주) |
| **목표 기록 피커** | 질문("목표 기록도 정해볼까요?") + 종목 표기(풀코스 42.195km) → 프리셋 칩(완주 / sub-5 / sub-4:30 / sub-4) → 시:분 2휠 → 페이스 환산("= km당 6'24\"") → CTA "이 기록으로 할게요" / 스킵 "일단 완주부터요" |
| **결과 카드** | "진단 결과" → 레벨명(런린이) → 한 줄 설명("완주와 습관부터, 같이 갑니다") → 🥚 → "알이 도착했어요 / 달릴수록 부화가 가까워집니다. 정상은 아니지만 멋있을 예정입니다." → CTA "건강 데이터 연결하기"(다음 화면에서 Apple 건강 읽기 권한 요청) |

### 목표 기록 피커 상세

- **시:분 2휠.** 현재 설정 화면의 시:분:초 3휠에서 초를 뺀다 — 목표 설정에 초 단위는 과하다.
- **실시간 페이스 환산** — 휠을 돌리면 `= km당 6'24"`를 즉시 갱신 (tabular-nums 고정폭).
- **종목별 프리셋 칩** — 5K: 30분·25분 / 10K: 60분·50분 / 하프: 2:00·1:50 / 풀: 완주(5:00)·4:30·4:00. 칩을 탭하면 휠이 그 값으로 이동한다.
- **현실성 판단은 훈련 가이드 몫.** 피커는 종목별 하한(세계기록 밑)만 막는다. "목표가 공격적"이라는 진단은 기록이 쌓인 뒤 Riegel 예측과 비교해서 한다 — 온보딩 시점엔 데이터가 없으므로 판단하지 않는다 (미노출 가드).
- 설정 화면의 목표 수정도 이 피커를 그대로 재사용한다 (§7).

## 3. 레벨 체계 — 3단계

2단계(런린이/런친놈)를 3단계로 나눈다. 기준은 설문 답에서 기계적으로 판정할 수 있도록 결정표로 고정하고, 경계가 애매하면 아래 레벨로 배정한다.

| 레벨 | 이름 | 기준 (설문 기준) | 리포트 초점 |
|---|---|---|---|
| **L1** | 런린이 | 러닝 경험 없음, 또는 아래 기준 미달 전부 | 완주 · 습관 형성 · 부상 예방 |
| **L2** | 런잘알 | 10km 1시간 이내 기록 보유, 또는 하프 이상 완주 | 기록 향상 · 훈련 구조화 |
| **L3** | 런친놈 | 풀코스 4시간 30분 이내 완주 **그리고** 월 마일리지 200km 이상 (둘 다 충족) | 부하 관리 · 정밀 지표 |

### 판정 결정표 (위에서부터 순서대로 평가)

| 순서 | 조건 | 판정 |
|---|---|---|
| 1 | Q1 = "이제 시작해요" | 런린이 |
| 2 | Q2 = 풀코스 완주 **AND** Q3(풀) = 4:30 이내 **AND** Q4 = 200km 이상 | 런친놈 |
| 3 | Q2 = 하프~풀 또는 풀코스 완주 (2번 미충족) | 런잘알 |
| 4 | Q3(10km) = "1시간 이내" | 런잘알 |
| 5 | 그 외 전부 | 런린이 |

- **애매하면 하향 배정.** 상위 레벨 리포트를 하위 실력자에게 주면 이해 못 하는 처방과 부하 지표 과신으로 다칠 수 있다. 반대는 심심할 뿐이다 — 다치는 쪽을 막는다. 미노출 가드와 같은 철학이다.
- **하프 이상 완주자는 최소 L2.** 10km 기록을 안 재봤어도 하프 완주는 그에 상당하는 지구력 증거로 간주한다. 대신 이 경우 Q3를 건너뛰어 문항 수도 준다.
- **판정은 순수 로직(`LevelEngine`)** 으로 구현하고 결정표 그대로 유닛 테스트를 붙인다.

### 중급 레벨 이름 — 런잘알 (확정)

런린이(런+어린이) → **런잘알**(러닝 좀 아는 사람) → 런친놈(런+미친놈)으로 확정했다. 후보였던 런른이·런소년은 기각 — 수준 뉘앙스가 가장 정확한 이름을 택했다.

### 재판정과 승급

- **다시 진단받기** — 설정 → 내 프로필에서 언제든 재설문 (§7). 답과 판정을 갱신한다.
- **실데이터 승급 제안** — 워치 기록에서 상위 레벨 근거를 감지하면(예: 10km 60분 이내 세션 발견, 또는 최근 4주 월환산 200km + 풀 4:30 이내 기록) 홈에 승급 제안 카드를 1회 띄운다. 수락하면 승급, 거절하면 4주간 다시 묻지 않는다.
- **자동 강등은 없다.** 성장 서사를 지킨다 — 내려가는 길은 본인의 재설문뿐이다.
- **레벨과 성장 단계는 직교.** 레벨(실력)은 리포트 깊이를, 성장 단계(§5, 활동 누적)는 홈 화면 보상을 결정한다. 런친놈도 알부터 키운다.

## 4. 레벨별 경험 차별화 — 권고안

"레벨별로 진입 UI를 다르게 할 것인가, 같은 화면에서 리포트 수준을 차별화할 것인가"는 미결 문제였다. 이 문서는 후자(B안)를 권고한다.

| 안 | 내용 |
|---|---|
| **A안 — 레벨별 진입 UI 분리** | 레벨마다 다른 첫 화면·다른 구성. 수준별 몰입감은 있으나, 5탭 × 3레벨의 화면 조합을 만들고 검증(스크린샷·QA·심사)까지 3벌로 늘어난다. 승급하면 배웠던 화면이 통째로 바뀐다. |
| **B안 — 동일 화면 + 콘텐츠 수준 차별화 (권고)** | 화면 구조는 하나. 레벨은 엔진의 입력이 되어 **어떤 지표를 내보낼지**와 **어떤 문장으로 말할지**만 바꾼다. 승급하면 같은 화면에서 새 지표가 해금된다. |

### B안의 근거

- **구조가 이미 그렇게 생겼다.** 엔진 → 스토어 → 화면 3계층에서 "무엇을 보여줄지"는 엔진 소관이다. `TrainingGuideEngine`은 이미 레벨을 입력받아 문장을 바꾸고 있다 — 같은 길을 넓히면 된다.
- **성장 서사와 시너지.** 승급 = 같은 화면에서 지표 해금. "해금"은 §5 성장 시스템과 한 몸의 경험이 된다. 화면이 통째로 바뀌면 학습 비용이 다시 들고 앱 정체성이 갈라진다.
- **시각적 차별화는 이미 새가 담당한다.** 홈의 새 성장 단계가 사용자마다 다르다 — 진입 UI까지 다르면 과잉이다.
- **미노출 가드와 같은 메커니즘.** "표본이 부족하면 안 내보낸다"에 "수준이 안 맞으면 안 내보낸다"를 더하는 것 — 새 개념이 아니라 기존 가드의 확장이라 구현·테스트가 단순하다.

단, 두 가지는 레벨별로 다르게 간다: **온보딩 직후 안내·빈 화면 문구**는 레벨별 문장으로, **런린이에게는 입문 전용 카드**(걷뛰 가이드 등)를 리포트 상단에 추가할 수 있다 — 숨기기만 하는 차별화가 아니라 더하는 차별화도 허용한다.

### 지표 노출 매트릭스

| 지표 / 카드 | 런린이 | 런잘알 | 런친놈 |
|---|---|---|---|
| 거리 · 시간 · 꾸준함(주간 목표·streak) | ● | ● | ● |
| 체력 배터리 | ● (쉬운 문장) | ● | ● |
| 주간 거리 · 10% 룰 | 문장만 — "이번 주 갑자기 많이 늘었어요" | ● 수치 | ● 수치 |
| 부하 비율 (ACWR) | – | ● | ● (수치+구간) |
| 심박 효율 (EF) | – | ● | ● |
| 심폐 체력 (VO₂max) 추세 | – | ● (요약) | ● |
| 주법 (케이던스·보폭 등) | – | ● | ● |
| 크로스 트레이닝 요약 | ● | ● | ● |
| 훈련 가이드 | 걷뛰·완주 프로그램 | 마일리지 + LSD 처방 | 페이스 존 세션 포함 |
| 문장 톤 | 용어 풀어쓰기 | 표준 | 압축 · 수치 중심 |

> **가드 우선순위** — 미노출 가드(표본 부족)가 레벨 게이트보다 항상 위다. 런친놈이라도 4주치 기록이 없으면 ACWR은 나오지 않는다.

## 5. 성장 시스템 — 알에서 나는 새까지

"런미새"에서 새는 지금까지 이름뿐이었다. 이제 실체를 준다 — 온보딩을 마치면 알을 하나 받고, 달릴수록 새가 자란다. §4.11 보이스의 화자가 바로 이 새다: 문장 톤의 주인이 생긴다.

### 성장 6단계

| 단계 | 이름 | 누적 XP |
|---|---|---|
| 1 | 알 | 0 XP |
| 2 | 금 간 알 | 50 XP |
| 3 | 부화 | 200 XP |
| 4 | 어린 새 | 500 XP |
| 5 | 날갯짓 | 1,000 XP |
| 6 | 나는 새 | 1,800 XP |

> **이모지는 자리표시다.** 실제 이미지(새 종류·일러스트)는 별도 제공 예정 — 수급 스펙은 §10. 단계 수 6은 제안값으로, 에셋 수급에 맞춰 조정한다.

### XP 산식 (초안 — 수치는 튜닝 전제)

| 행동 | XP | 설계 의도 |
|---|---|---|
| 러닝 1회 완료 (1km 이상) | +10 | 나간 것 자체를 보상 |
| 거리 보너스 | +1 / km (회당 상한 +21) | 하프를 넘겨도 그 이상 안 준다 — 과부하 비보상 |
| 주간 목표 달성 (주 N회 — Q5 초기값, 설정 변경 가능) | +30 | 꾸준함이 최우선 보상 |
| 주간 목표 4주 연속 달성 | +50 | 기존 `streakWeeks` 엔진을 재료로 승격 |
| 일일 상한 | 40 | 몰아 뛰기 방지 |

- **거리보다 꾸준함.** 과부하를 보상하지 않는다 — "과부하를 자랑거리로 만들지 않는다"는 칭호 시스템(§4.12)의 원칙과 같은 선이다.
- **퇴행 없음.** 안 뛰어도 XP는 깎이지 않고 새는 어려지지 않는다. 벌점은 이탈을 낳는다.
- **레벨 무관 동일 산식.** 모두 알부터 시작한다 — 숙련자는 자연히 빨리 큰다. "성장하는 재미"는 모든 수준에 준다는 요구의 답이다.
- **컨디션 표현 (확정)** — 7일 이상 기록이 없으면 새가 시무룩한 표정이 된다. 퇴행이 아니라 표정 변화이고, 다시 달리면 바로 풀린다. 시무룩 이미지는 별도 제공 확정 (§10).

### 도달 시뮬레이션 (주간 목표 달성 가정)

| 페르소나 | 주당 XP | 금 간 알 | 부화 | 어린 새 | 날갯짓 | 나는 새 |
|---|---|---|---|---|---|---|
| 런린이 주 2회 × 3km | 56 (+streak) | 1주 | 4주 | 8주 | 16주 | 27주 |
| 런잘알 주 3회 × 5km | 75 (+streak) | 1주 | 3주 | 6주 | 12주 | 21주 |
| 런친놈 주 5회 × 10km | 130 (+streak) | 1주 | 2주 | 4주 | 8주 | 13주 |

- **첫 반응은 첫 주 안에.** 어떤 페르소나든 1주차에 금 간 알을 본다 — 초반 보상은 빠르게.
- **마지막 단계는 시즌 단위.** 나는 새까지 3~6개월 — 한 시즌을 함께 달린 증표가 된다.
- **성조(나는 새)는 끝이 아니라 한 사이클의 완성** — 도달하면 수집 세러모니와 함께 도감에 수록되고, 새 목표와 함께 새 알을 받는다.

### 성장 사이클과 새 수집 (확정)

성장은 1회성이 아니라 사이클이다. 성조에 도달하면 그 새를 도감에 수집하고, 새 목표와 함께 새 알에서 다시 시작한다. 사이클마다 다른 새를 키우게 되므로 "성장하는 재미"가 목표를 갱신할 때마다 새로 채워진다.

```
성조 도달
   ↓
수집 세러모니 — 축하 애니메이션 + 도감 수록
   ↓
새 목표 추천 화면 (직전 목표·최근 기록 기반으로 다음 목표를 제안 — 직접 설정도 가능)
   ↓
새 알 지급 — 새 사이클 시작
```

- **새 종류는 그 사이클의 목표 수준이 정한다.** 낮은 목표는 참새 같은 작은 새, 서브3는 백조 같은 큰 새 — 도감이 곧 러너로서의 이력이 된다.
- **수집창(도감)** — 수집한 새를 성조 이미지 + 당시 목표 + 수집일과 함께 보여주는 화면. 홈의 새 스테이지에서 진입한다 (별도 탭은 만들지 않는다 — 5탭 유지).
- **세러모니 애니메이션** — 외부 의존성 없음 원칙이라 Lottie는 쓰지 않는다. SwiftUI 애니메이션(필요 시 Canvas·TimelineView 파티클)으로 구현한다.
- **사이클과 XP** — XP 계산 시작점이 온보딩 시각에서 **사이클 시작 시각**으로 일반화된다 (첫 사이클 = 온보딩). 산식과 단계 임계값은 모든 사이클에서 동일하다.
- **"성장은 되돌리지 않는다"와의 정합** — 새 알은 퇴행이 아니다. 수집한 새는 도감에 영구히 남고, 알은 새로운 새다.

| 사이클 목표 (그 사이클의 목표 레이스·기록) | 새 (초안) |
|---|---|
| 목표 없음 · 완주 습관 | 참새 |
| 5K · 10K | 제비 |
| 하프 | 매 |
| 풀 완주 (sub-5) | 기러기 |
| 풀 sub-4 ~ sub-3:30 | 두루미 |
| 풀 sub-3 (서브3) | 백조 |

> **매핑은 초안이다.** "서브3 = 백조"만 확정 축이고, 나머지 종과 등급 경계는 에셋 수급과 함께 확정한다 (§12).

### 구현 노트 — GrowthEngine

- **순수 로직.** Foundation만 import, `now` 주입, 결정론적 — 엔진 계층 규칙 그대로. 유닛 테스트 필수.
- **XP 원장을 따로 저장하지 않는다.** XP는 현재 사이클 시작 시각 이후의 HealthKit 러닝 이력에서 매번 결정론적으로 재계산한다 — 저장·동기화 문제가 사라진다. 저장할 값은 주간 목표(현재값), 사이클 시작 시각, 이번 사이클 최고 단계, 그리고 수집 도감뿐.
- **표시 단계 = max(계산 단계, 저장된 최고 단계).** 주간 목표를 바꾸거나 건강 데이터가 지워져 계산값이 흔들려도 새는 어려지지 않는다 — "성장은 되돌리지 않는다"의 구현 장치.
- **과거 이력은 XP에 산입하지 않는다.** 온보딩 첫날 성조가 되면 키우는 재미가 없다 — 알부터 키우는 경험을 보장한다. 단, 레벨 판정·리포트는 과거 이력을 그대로 쓴다.
- **주간 목표 판정은 ISO 주 기준** (기존 `streakWeeks`와 동일), 화면 표기는 `Format.weekLabel` 규칙("8월 2째주")을 따른다.
- **칭호(§4.12)와 독립.** 칭호는 세션 단위 순간 재미(공유 카드), 성장은 누적 보상(홈). 칭호 획득의 XP 가산은 없다 — 단순하게 간다.

## 6. 홈 탭 신설과 탭 재편

첫 화면의 주인공을 지표에서 새로 바꾼다. 성장이 먼저 보이고, 최근 기록 브리핑은 한두 문장이면 충분하다. 지표 카드 나열은 리포트 탭의 일이다.

### 탭 재편 — 5탭 유지

| | 현재 | 개편 |
|---|---|---|
| **탭** | 리포트 · 통계 · 오늘 · 코스 · 대회 | **홈** · 리포트 · 오늘 · 코스 · 대회 |
| **통계** | 독립 탭 | 리포트 탭 상단 세그먼트 [이번 주 \| 발전상]로 흡수 |

iOS 탭바는 5개를 넘기면 More 탭으로 밀린다 — 홈을 넣으려면 하나를 합쳐야 하고, 성격이 가장 가까운 리포트+통계를 합친다. 홈 탭 아이콘은 새 실루엣(커스텀, §10)이다.

### 홈 화면 구성

| 순서 | 구역 | 내용 |
|---|---|---|
| 1 | **새 스테이지** (상단 ~45%) | 새 이미지 크게 + 단계명 + 다음 단계까지의 XP 게이지. 탭하면 새가 반응(에셋 여력 시). 성조 도달 시 수집 세러모니로 전환하고, 수집창(도감) 진입점도 여기에 둔다 (§5) |
| 2 | **오늘의 브리핑** (1~2문장) | 엔진 결과 중 최우선 1개만, 런미새 보이스로. 우선순위: ① 과부하·부상 경고 ② 컨디션 변화(배터리·EF) ③ 꾸준함 칭찬 ④ 날씨 한 줄 |
| 3 | **최근 러닝 칩** | 날짜 · 거리 · 페이스 한 줄 → 탭하면 세션 상세 |
| 4 | **주간 목표 칩** | 이번 주 N회 중 M회 — §5 주간 목표와 동일 값 |

와이어프레임 예시: 새 스테이지(🐤 "어린 새 · 4단계", 게이지 + "다음 단계까지 190 XP") → 브리핑("이번 주 3번째 러닝. 지난주보다 12% 늘었어요 — 딱 좋은 증가폭입니다. 정상은 아니지만 멋있습니다.") → 칩 2개("어제 러닝 5.2km · 5'41\"", "이번 주 목표 2 / 3회").

- **글자 최소.** 홈의 텍스트는 브리핑 1~2문장과 칩 라벨이 전부다. 상세 지표·차트는 전부 리포트 탭으로.
- **미노출 가드.** 기록이 없으면 브리핑 대신 첫 안내만 — "첫 러닝을 기다리고 있어요. 알도 기다리고 있습니다."
- **리포트 탭**은 현행 카드 구성을 유지하되 §4 매트릭스대로 레벨 게이트를 적용하고, 다이어트 전용 배치 분기(칼로리·몸무게 카드 우선)는 제거한다. streak 카드는 홈의 주간 목표 칩으로 승격되어 전 레벨에 보인다.

## 7. 설정 화면 개편

목적·레벨 토글을 없애고 "다시 진단받기"로 바꾼다. 몸무게 관련은 전부 제거, 성장 시스템의 주간 목표가 새로 들어온다. 7섹션 → 3그룹.

| 현재 섹션 | 처리 | 개편 후 |
|---|---|---|
| 러닝 목적 (다이어트/훈련) | 삭제 | 온보딩 Q9(달리는 이유)로 흡수 — 재진단으로만 변경 |
| 러닝 레벨 (2단계 토글) | 대체 | **① 내 프로필·목표** — 현재 레벨 표시(배지) + **다시 진단받기**(재설문 진입) / 주간 러닝 목표 (주 N회 — §5 XP 연동, 신설) / 목표 레이스 · 목표 기록 (온보딩과 같은 피커 재사용, 시:분 2휠) |
| 목표 레이스 / 목표 기록 (시:분:초 3휠) | 개편 | ↑ 위와 같은 그룹으로 통합 |
| 알림 3종 (운동 직후 · 주간 리포트 · 수분 알람) | 유지 | **② 알림** — 현행 그대로 |
| 데모 모드 / 개인정보 처리방침 | 유지 | **③ 앱 정보** — 데모 모드 · 개인정보 처리방침 · 데이터 출처 표기 |

> **레벨을 토글로 두지 않는 이유** — 3단계 기준(§3)은 기록 기반이라 자기 신고 토글과 어긋날 수 있다. 변경 경로를 재설문(다시 진단받기)과 실데이터 승급 제안으로 좁혀야 레벨의 의미가 유지된다.

## 8. 몸무게 트래킹 제거

v0.3에서 넣었던 몸무게 추이를 철회한다. HealthKit bodyMass 읽기 권한 요청까지 포함해 전부 걷어낸다 — 건강 데이터 추적 범위 자체를 줄이는 결정이다.

| 파일 | 대상 | 처리 |
|---|---|---|
| `HealthPermissions.swift:39-42` | diet 전용 권한 Set (`bodyMass`) | 삭제 — 권한 요청 경로 소멸 |
| `HealthStore.swift:22, 65-70, 342-349` | `bodyMass` published · `requestDietAccess()` · `fetchBodyMass()` | 삭제 (`load()`의 호출부 포함) |
| `ReportHomeScreen.swift:85-90, 214-254` | 다이어트 카드 우선 배치 분기 · `weightCard` · `weightHeadline` | 삭제 |
| `ReportMetrics.swift:250, 273-291` | `WeightTrend` · `weightTrend()` | 삭제 |
| `ReportMetricsTests.swift:200-231` | 몸무게 추이·가드 테스트 2개 | 삭제 — 기능 제거에 따른 스펙 삭제 (실패 테스트 무단 삭제와 다름) |
| `UserProfile.swift` | `RunGoal`(diet/training) enum과 `profile.goal` 키 | 제거 — §9 프로필 v2로 대체 |
| `OnboardingScreen.swift:139-141` · `SettingsScreen.swift:30-39` | 다이어트 선택 시 `requestDietAccess()` 트리거 | 온보딩·설정 재작성과 함께 소멸 |
| `ReportHomeScreen.swift` 칼로리 카드 | 다이어트 모드 전용 노출 | 폐기 (확정) — 칼로리 카드 자체를 제거한다 |

- **권한 문구는 이미 정합.** `NSHealthShareUsageDescription`(project.yml:53)은 "거리·시간·심박"만 언급한다 — bodyMass 제거로 문구와 실제 요청 범위가 오히려 일치하게 된다. 앱스토어 문안(store-listing.md)에도 몸무게 언급이 없어 스토어 영향 없음.
- **기존 설치자의 bodyMass 권한**은 앱이 더 이상 읽지 않으므로 무해하다. 건강 앱의 권한 목록 정리는 사용자 몫으로 남긴다 (앱이 개입할 방법이 없다 — 애플 정책).

## 10. 에셋 요구 명세

새 이미지는 별도 제공 예정이다. 제공이 순조롭도록 수급 스펙을 먼저 고정한다 — 이 스펙과 다르게 제작되면 §5 단계 수를 에셋에 맞춰 조정한다.

| 항목 | 스펙 |
|---|---|
| **성장 단계 이미지** | 6종 — 알 / 금 간 알 / 부화 / 어린 새 / 날갯짓 / 나는 새 |
| **상태 변형 (확정)** | 시무룩 표정 — 부화 이후 4단계 × 각 1종. 별도 제공 확정 |
| **종별 성조 이미지** | 수집 도감용 — 종당 성조 1종 (참새~백조, §5 매핑). 에셋 부담을 줄이려면 1~5단계는 전 종 공통으로 두고 성조만 종별로 제작하는 안을 권장 |
| **포맷** | 투명 배경 PNG @2x/@3x, 또는 벡터(PDF/SVG) 1종 — 벡터 우선 |
| **권장 원본 크기** | 1024 × 1024 (홈 스테이지 최대 표시 ~300pt) |
| **배경 대응** | 웜 크림(#F2F0EA)·다크(#0A0A09) 모두에서 또렷하게 — 외곽선 또는 밝은 톤 권장 |
| **스타일** | 시안 v0.4 "스포티 볼드"와 어울리는 단순·볼드 일러스트. 작은 크기(온보딩 결과 카드 ~90pt)에서도 뭉개지지 않아야 함 |
| **파일명 규칙** | `bird-stage-1` ~ `bird-stage-6` · 시무룩은 `-sulky` 접미사 · 종별 성조는 `bird-adult-sparrow`처럼 종명 접미사 — Asset Catalog 등록 |

## 11. 구현 로드맵

다섯 단계로 나눈다. 각 단계는 독립적으로 빌드·테스트가 통과하는 상태로 끝난다. 기존 로드맵 13단계(런미새 보이스&톤)는 G5에 병합한다.

| 단계 | 내용 | 완료 기준 | 예상 규모 |
|---|---|---|---|
| **G1** | 프로필 v2 + `LevelEngine` + 온보딩 카드 플로우 (§2·§3·§9) | 설문 → 판정 → 저장 동작 · 결정표 유닛 테스트 통과 · 시뮬레이터 플로우 스크린샷 확인 | 2~3일 |
| **G2** | 몸무게 제거 + 설정 재편 (§7·§8) | `bodyMass` 참조 0건 · 전체 테스트 통과 (몸무게 테스트 2개는 스펙 삭제) | 반나절~1일 |
| **G3** | `GrowthEngine` + 홈 탭 + 탭 재편 (§5·§6) — 자리표시 에셋 | XP 재계산 결정론 테스트 · 홈/리포트 세그먼트 시뮬레이터 확인 | 2~3일 |
| **G4** | 레벨별 리포트 게이트 (§4) | 노출 매트릭스 그대로 동작 — 레벨×지표 게이트 테스트 | 1~2일 |
| **G5** | 실에셋 반영 + 런미새 보이스 전수 리라이트 (기존 13단계 병합) | 새 이미지 6종 + 시무룩 변형 적용 · 노출 문장 톤 적용 · 스크린샷 6장 갱신 | 2~3일 + 에셋 대기 |
| **G6** | 수집 시스템 — 사이클 전환 · 수집창(도감) · 세러모니 · 새 목표 추천 (§5) | 사이클 리셋·도감 수록 결정론 테스트 · 세러모니 시뮬레이터 확인 | 2~3일 + 종별 에셋 |

> **순서 근거** — G1(프로필 구조)이 모든 단계의 토대라 먼저다. G2(제거)는 작고 독립적이라 이른 시점에 끝내 코드베이스를 가볍게 한다. G5·G6는 외부 에셋 수급에 의존하므로 뒤에 두되, G3의 자리표시 에셋으로 그 전까지의 개발·검증이 막히지 않게 한다. G6(수집)는 첫 사용자가 성조에 도달하기까지 3개월 이상 여유가 있어(§5 시뮬레이션) 출시 후 업데이트로 나가도 된다.
