## 1. M13-1 — 크롤러 + 데이터 (`tools/race-info/crawl.py`)

- 목록 `schedule/list.php`(기본값이 예정 대회만)에서 `view.php?no=<id>` 링크로 대회 ID 수집
  → 상세 페이지의 라벨 셀(`bgcolor="#86B7DF"`)·값 셀(`bgcolor="white"`) 쌍을 정규식으로 파싱.
- 산출물은 `ios/RunWrap/Races.json` 하나 — **앱 번들 리소스이자 raw URL 배포 원본**
  (sources가 폴더 단위라 xcodegen이 자동 포함, 파일 하나·URL 하나로 이원화 없음).
- 스키마: `{generatedAt, source, races[]}`. race는 `id`·`name`·`date`(yyyy-MM-dd)만 필수,
  나머지(`startTime`·`region`·`place`·`host`·`categories`·`registerStart`·`registerEnd`·
  `homepage`·`lat`·`lon`·`note`)는 **없으면 키 자체를 생략** — 앱의 미노출 가드와 짝.
- 파싱 성공률 80% 미만이면 exit 1 — 사이트 개편 감지 장치.
- **결과**: 216/216건(8~12월) 파싱 성공. startTime만 54건 누락(원천에 없음), 나머지 필드는 전건 확보.

## 2. M13-2 — RaceEngine (순수 로직) + 테스트

- **Race/RaceFile** 모델 + **RaceEngine**: KST 달력 고정, `now: Date` 주입으로 결정론적.
- 접수 상태는 날짜 단위 판정 — 시작일 ≤ 오늘 ≤ 마감일이면 **접수중**(마감 당일 포함),
  오늘 < 시작일이면 **접수예정**, 오늘 > 마감일이면 **접수완료**.
  시작·마감을 둘 다 모르면 nil(배지 미노출), 마감만 모르면 `open(end: nil)`.
- 대회일이 지난 대회는 목록에서 제외, (대회일, id) 오름차순 정렬.
  대회 D-day와 마감 D-day를 함께 계산한다.
- **결과**: Swift Testing 10건 통과 — 상태 3종·마감 당일·미상 가드·지난 대회 필터·
  정렬·날짜 형식 오류·실데이터 Races.json 디코딩까지 커버.

## 3. M13-3 — RaceStore + 화면 + 탭

- **RaceStore**: `@MainActor` + `ObservableObject` + `enum State` 규칙 유지.
  로컬(캐시 vs 번들 중 generatedAt이 최신인 쪽)을 먼저 보여주고 원격을 뒤에서 갱신 —
  첫 화면이 네트워크를 기다리지 않고, 원격 실패 시 마지막 자료로 동작한다.
  원격은 raw.githubusercontent.com, 성공 시 Application Support에 캐시.
  **요청에 사용자 데이터를 싣지 않는다** (수신 전용, 기획서 §6).
- **RaceListScreen**: 날짜 열 + 대회명·종목·지역·접수기간 + 접수 상태 배지·D-day 행 카드.
  헤더에 "지금 접수받는 대회 N곳 · M월 d일 갱신", 당겨서 새로고침.
  **RegisterBadge**는 훈련 상태(RRTone)가 아니라 모집 상태라 IndoorBadge처럼 별도 색 매핑.
- **RaceDetailScreen**: D-day·배지·대회명 헤더, 종목 칩, 정보 카드(일시·장소·접수기간·주최),
  대회장 지도(MapKit, 좌표 있을 때만), "대회 소개" 원문 카드, **참가하기** 버튼(홈페이지 Link),
  하단에 출처(로드런)·"참가 전 대회 홈페이지에서 꼭 확인" 고지.
- **RootView**: 5번째 탭 "대회" (flag.checkered).
- **결과**: 전체 139개 테스트 통과, 시뮬레이터에서 목록·상세 스크린샷 검증 완료.

## 4. M13-4 — GitHub Actions 일일 배치 (`.github/workflows/race-info.yml`)

- 매일 05:00 KST(cron `0 20 * * *`) + 수동 실행(workflow_dispatch).
- 크롤 → `generatedAt` 변동은 무시하고 **races 내용이 바뀐 날만** github-actions[bot]으로 커밋
  (커밋 소음 방지). 크롤 실패(성공률 80% 미만 포함)면 잡 실패로 개편을 알아챈다.
- 저장소에 푸시된 뒤부터 동작한다 — 첫 확인은 workflow_dispatch 수동 실행으로.
