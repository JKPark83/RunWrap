> **버전**: v0.6
> **작성일**: 2026-08-12 (v0.2: 확장 요구사항 7건 + 사용자 프로필 반영 / v0.3: 다이어트 몸무게 추이 추가, 실내/야외 통계 통합 / v0.4: 런미새 보이스&톤·칭호 시스템 추가 / v0.5: 코스 보급 가이드 — 4번째 탭 추가 / v0.6: 대회 캘린더 — 5번째 탭 추가)

## 1. 한 줄 정의

애플워치에 쌓인 러닝 데이터를 **러너에게 의미 있는 지표로 재가공**해 주기적으로 알려주고, 탭 한 번으로 **인스타그램에 올릴 수 있는 카드 이미지**를 만들어주는 아이폰 전용 앱.

표시 이름은 **런미새**(러닝에 미친 사람). 모든 사용자 노출 문장은 "러닝에 미친 정중한 동료 러너"의 목소리로 쓴다 — §4.11.

---

## 2. 배경 및 문제 정의

### 2.1 기존 도구의 공백

- 애플 기본 건강/피트니스 앱은 **원시 데이터 나열**에 가깝다. "이번 주 부하가 위험 수준인가", "컨디션이 오르고 있는가" 같은 질문에 답하지 않는다.
- 러너가 SNS에 기록을 공유하려면 스크린샷 → 편집 앱 → 인스타그램의 3단계를 매번 반복해야 한다.
- 서버 기반 자동 게시는 Instagram Graph API의 제약(프로페셔널 계정, Facebook 페이지 연동, Meta 앱 심사 2~4주)과 HealthKit의 구조적 제약(클라우드 API 부재, 잠금 시 접근 불가)으로 개인이 운영하기에 비용 대비 효율이 낮다.

### 2.2 설계 원칙

1. **온디바이스 우선** — 서버 없이 기기에서 읽고, 계산하고, 렌더링한다.
2. **자동 게시가 아닌 원탭 공유** — 사용자 탭이 개입하므로 Meta 심사 파이프라인을 완전히 우회한다.
3. **알림은 정확하게, 계산은 미리** — iOS 백그라운드 실행의 불확실성을 알림/계산 분리로 흡수한다.

## 4. 핵심 기능

### 4.1 건강 데이터 수집 (HealthKit)

- `HKWorkoutType` 러닝 세션: 거리, 시간, 페이스, 칼로리
- `HKQuantityType`: 심박, 케이던스, 파워(지원 기기), 걸음 수, 몸무게(bodyMass — 다이어트 모드 추이용, v0.3)
- `HKWorkoutRoute`: GPS 경로 (지도 카드 렌더링용)
- 읽기 전용 권한만 요청. 쓰기 권한 불필요.

### 4.2 러너 특화 리포트 (차별화 핵심)

기본 앱이 보여주지 않는 **파생 지표**를 계산한다:

| 지표 | 의미 | 알림 예시 |
|---|---|---|
| 주간 거리 증가율 | 10% 룰 위반 감지 | "지난주 대비 +23% — 과부하 구간입니다" |
| ACWR (급성:만성 부하비) | 부상 위험 지표 | "이번 주 부하가 4주 평균의 1.6배입니다" |
| 심장 드리프트 | 같은 페이스 대비 심박 추이 = 컨디션 프록시 | "동일 페이스 심박이 3주째 하락 중 — 체력이 오르고 있습니다" |
| 케이던스/보폭 추이 | 러닝 폼 변화 | "케이던스가 평균 대비 5% 낮았습니다" |

> **원칙**: "오늘 5km 뛰었습니다"는 아무도 열지 않는다. 알림은 반드시 **해석된 인사이트**를 담는다.
> v0.4 확장: 해석만으로는 부족하다 — **읽는 재미가 있어야 다시 연다** (§4.11).

### 4.3 주기적 알림

- 사용자가 리포트 주기 설정: 매일 / 매주 / 운동 직후
- `UNCalendarNotificationTrigger`로 알림 시각은 정확하게 보장
- 리포트 본문은 사전 계산·캐시, 앱 진입 시 최신 데이터로 갱신

### 4.4 인스타그램 공유 카드

- "공유하기" 탭 → 9:16 세로 카드 이미지 생성 (SwiftUI `ImageRenderer`)
- 카드 구성: 날짜, 거리, 페이스, 심박 존, 경로 지도(MapKit 스냅샷), 주간 요약
- `instagram-stories://` URL 스킴으로 **인스타그램 스토리 편집 화면에 즉시 진입**
- 폴백: 인스타그램 미설치 시 공유 시트(`UIActivityViewController`) / 사진 앱 저장

### 4.5 사용자 프로필 — 목적·레벨 (v0.2 신규)

- 온보딩에서 2가지를 설정하고, 설정 화면에서 언제든 변경할 수 있다:
  - **목적**: 다이어트 / 훈련(퍼포먼스) 중 택1
  - **레벨**: 초보자 / 숙련자 중 택1
- 프로필은 **리포트 구성과 처방 문장을 전환**한다:
  - 다이어트: 칼로리·누적 소모·꾸준함(연속 훈련 주)·몸무게 추이 카드를 앞세우고, 처방은 "감량 페이스 유지" 톤.
    몸무게는 HealthKit bodyMass(건강 앱·스마트 체중계 기록)를 읽어 주 단위 변화 추이로 그린다 (v0.3)
  - 훈련: 현행 그대로 부하(ACWR)·심박 효율·훈련 가이드 중심
  - 초보자: 완주·부상 예방 중심의 쉬운 문장, 숙련자: 페이스·존 수치를 그대로 노출
- 저장은 로컬(AppStorage) — 서버 없음 원칙 유지

### 4.6 트레드밀/야외 구분 (v0.2 신규)

- `HKMetadataKeyIndoorWorkout`으로 실내(트레드밀)/야외 러닝을 구분해 목록·상세에 배지 표시
- 구분은 세션 단위 표시까지만 — 통계·리포트는 실내/야외를 하나의 러닝 데이터로 합산한다
  (v0.3에서 분리 집계 철회). 트레드밀은 GPS가 없어 경로·고도 카드가 빠지고,
  주법 지표도 야외에서만 기록된다 — §4.8

### 4.7 퍼포먼스 발전상 — 통계 탭 확장 (v0.2 신규)

- 월별 페이스·심박 효율(EF)·거리의 장기 추이 차트 — "내가 얼마나 발전했는가"를 한 화면에
- 개인 최고 기록(PR) 하이라이트: 5K / 10K / 하프 / 풀 별 최고 기록과 달성일

### 4.8 주법(러닝 폼) 리포트 (v0.2 신규)

- watchOS 9+ 러닝 다이내믹스 지표: 수직 진폭, 지면 접촉 시간, 보폭, 러닝 파워 + 케이던스(걸음 수 파생)
  - Apple Watch SE·Series 6 이상 + watchOS 9 이상에서 시스템이 자동 기록하며,
    **야외 러닝에만 남는다** (트레드밀 미기록 — 애플 문서 기준)
- 룰 기반 조언 문장: 페이스 대비 케이던스 부족, 수직 진폭 과다 등을 감지해 해석을 담아 알려준다
  - 예: "이 페이스대의 일반적인 케이던스는 170spm 이상인데 162spm이었어요 — 보폭을 줄이고 발걸음을 빠르게 가져가 보세요"
- 세션 상세에 주법 섹션 추가 + 주간 리포트에 추이 인사이트 1개
- 절대 기준이 아니라 **최근 4주 개인 기준선 대비 변화** 중심 (기존 미노출 가드 원칙 동일 적용)

### 4.9 훈련 가이드 — 진단·페이스·처방·오늘의 훈련 (v0.2 신규, v0.9 재설계)

- 목표 입력: 종목(5K/10K/하프/풀) + 목표 기록 + **대회 날짜(선택)** — 설정에서 함께 관리
- **진단**: 실제 러닝 세션으로 추정한 예상 완주 시간(Riegel 공식, 지수 1.06)과 목표의 갭.
  최근 1주 표본을 우선하고, 유효 표본이 없을 때만 4주→8주로 넓힌다. 표본은 5km 이상이며
  목표 거리/세션 거리 비율이 3배 이하여야 한다. 각 창 안에서는 예측이 가장 빠른 세션을 쓴다.
  목표 기록은 여기까지만 쓴다 — 훈련 페이스에는 반영하지 않는다 (목표에 페이스를 끌어올리면 부상 위험만 커진다)
- **훈련 페이스 존**: 진단이 선택한 실제 러닝 세션에서 Daniels VDOT을 역산해 (Daniels & Gilbert 1979)
  이지 62~74% / 템포 88% / 인터벌 97.5% 강도의 페이스를 낸다.
  기록이 좋아지면 VDOT이 오르고 페이스가 따라 올라간다 — "현재 실력 기준" 원칙
- **주기화**: 대회 날짜가 있으면 D-day 기준 단계를 낸다 —
  기초기 → 강화기 → 피크 → 테이퍼(풀 2주·하프 1주·5K/10K 0주) → 대회 주간.
  테이퍼는 주간 볼륨 ×0.6~0.7, 대회 주간 ×0.4~0.5 + LSD·퀄리티 제외
- **처방**(매주 갱신): 권장 주간 거리 / LSD 목표 거리 / 퀄리티(템포·인터벌) 횟수
  - 주간 거리: 최근 4주 평균(chronic)에 10% 룰 상한 + 종목×레벨별 피크 주간 km 상한
    (5K 20/30/45 · 10K 25/40/55 · 하프 35/50/70 · 풀 45/65/90 — 런린이/중급/고급)
  - LSD 목표치: 주간 하한의 25% ~ 상한의 35%. 체력 배터리가 나쁘면 하한으로만
  - 퀄리티 믹스: 단계×레벨별 템포/인터벌 0~2회 (기초기·테이퍼는 템포만, 배터리 제한 시 인터벌 제외)
  - 장거리/스피드 밸런스: 세션을 이지/LSD/스피드로 분류해 80/20 원칙과 비교 (Seiler)
- **오늘의 훈련**: 요일 고정이 아니라 최근 이력+배터리로 매일 판정 —
  ① 과부하면 휴식 → ② 주간 횟수 완료 → ③ 주간 거리 완료 → ④ 배터리 주의면 가볍게 →
  ⑤ 어제 고강도면 이지런(hard-easy 원칙) → ⑥ 주말 임박·LSD 미완이면 LSD →
  ⑦ 퀄리티 미달이면 템포/인터벌 → ⑧ 남은 거리를 이지런으로. 거리·페이스 존을 함께 낸다
- 표본 부족 시 미노출 가드 동일 적용 — 기록 3주 미만이면 처방 없음, 가장 넓은 8주 창에도
  최소 거리·3배 외삽 가드를 통과한 세션이 없으면 예상 기록·페이스 존 없음

### 4.10 '오늘' 탭 — 러닝 환경 (v0.2 신규, 3번째 탭)

- 현재 위치(또는 지정 위치) 기준 **온도·습도·풍속**을 아이콘+수치로 표시
- 체감온도 구간·강수·바람 조건에 맞는 러닝 복장을 **내장 일러스트 세트**로 추천
  (반팔/긴팔/자켓/장갑/모자/방풍 등 조합 — 이미지 생성 아님, 앱에 미리 그려 넣은 자산)
- **수분 섭취 권장 알람**: 예보 온도가 기준(예: 25°C) 이상인 날, 사용자가 설정한 러닝
  시간대 전에 로컬 알림 ("오늘 30°C 예보 — 러닝 1시간 전 500ml"). 설정에서 끌 수 있다
- 위치는 날씨 조회에만 사용하고, 건강 데이터와 결합해 외부로 보내지 않는다

### 4.11 런미새 보이스 & 톤 (v0.4 신규)

앱 정체성의 중심. 재미는 캐릭터도 게임 요소도 아닌 **문장 그 자체**에서 나온다.

- **페르소나**: 러닝에 미친 것을 자랑스러워하는, 정중한 말투의 동료 러너. 사용자를 "같은 미새"로 대우한다.
- **적용 범위**: 알림·리포트 인사이트·공유 카드 캡션·앱 전반 UI 카피(빈 화면, 온보딩, 설정) 전부.

| 규칙 | 내용 |
|---|---|
| 존댓말 위트 | 정중한 문장 끝에 반전 한 줄. 예: "정상은 아니지만 멋있습니다" |
| 사실 먼저, 위트는 뒤 | 수치·해석이 앞, 드립이 뒤 — 유머가 데이터를 왜곡하지 않는다 |
| 놀림의 대상은 "미친 상태"뿐 | 몸매·속도·기록을 비하하지 않는다 (다이어트 모드에서 특히) |
| 경고도 위트, 지시는 명확 | 과부하·부상 경고도 톤은 유지하되 마지막 줄은 반드시 행동 지시 |
| 미노출 가드 유지 | 데이터가 없으면 위트도 없다 — 억지로 말 걸지 않는다 |
| 반복 피로 방지 | 상황당 변형 3개 이상, 최근 사용 문장 회피 |
| "새" 말장난은 양념 | "오늘도 날개 대신 다리로 나셨군요" 수준으로 가끔만 |

문장 예시 (기존 → 런미새):

| 상황 | 기존 (v0.3) | 런미새 (v0.4) |
|---|---|---|
| 운동 직후 | "오늘 5.2km를 뛰었습니다" | "또 뛰셨네요. 이번 주 3번째입니다. 정상은 아니지만 멋있습니다" |
| 심장 드리프트 개선 | "동일 페이스 심박이 3주째 하락 중 — 체력이 오르고 있습니다" | "같은 페이스에 심박이 3주째 내려가는 중. 몸이 적응해 버렸습니다. 이제 되돌릴 수 없습니다" |
| 과부하 경고 | "지난주 대비 +23% — 과부하 구간입니다" | "지난주보다 +23%나 뛰셨습니다. 열정은 인정하는데 무릎은 인정 안 할 겁니다. 이번 주는 살살 가시죠" |

구현: 문장은 전부 앱 내장 **문장 뱅크**(PhraseBank — 순수 로직, 상황 키별 변형 배열, 시드 주입으로 결정론적 선택)에서 가져온다. LLM 생성은 쓰지 않는다 — 온디바이스·서버 없음 원칙 유지 (§10의 LLM 캡션은 v2+ 보류 그대로).

### 4.12 칭호 시스템 (v0.4 신규)

조건을 만족한 러닝에 칭호를 붙여 공유 카드의 "자랑+웃음" 콘텐츠로 쓴다.

| 칭호 | 조건 |
|---|---|
| 새벽 미새 | 오전 6시 이전 시작 |
| 야행성 미새 | 오후 10시 이후 시작 |
| 성실 미새 | 연속 훈련 4주 이상 (streak) |
| 장거리 미새 | 하프(21.0975km) 이상 완주 |
| 기록 미새 | PR 갱신 |

- 판정은 HealthKit 데이터만으로 가능한 것부터 한다 (TitleEngine — 순수 로직, `now` 주입, 미노출 가드 동일 적용).
- **과부하를 자랑거리로 만드는 칭호는 만들지 않는다** — 10% 룰 위반·ACWR 초과를 보상하면 부상을 조장한다.
- 우천·폭염 칭호("우천 완주 — 진짜 미친 새")는 러닝 시점의 날씨를 판정할 방법이 미해결이라 보류 — §11.

### 4.13 코스 보급 가이드 — GPX 코스 분석 (v0.5 신규, 4번째 탭 "코스")

장거리 러닝에서 실제로 중요한 세 가지 — **급수·화장실·보급** — 를 달리기 전에 미리 확인한다.

- GPX 파일(스트라바·가민 등에서 내보낸 코스)을 업로드하면, 코스의 몇 km 지점에서
  급수(음수대)·화장실·보급(편의점)을 이용할 수 있는지 계산해 보여준다.
- 화면 구성: 상단 지도(코스 폴리라인 + 종류별 POI 핀) + 하단 km 순 리스트
  — "3.2km 지점 · GS25 (코스에서 40m)". 지도 스타일은 세션 상세 화면과 통일.
- 매칭 기준: 코스에서 일정 반경(기본 150m, §11) 이내의 POI만 노출하고,
  코스 폴리라인에 수선을 내려 **누적 km 지점**과 **이탈 거리**를 계산한다.

**데이터 출처** (전부 앱에 번들, 조회는 온디바이스 — 2026-08 조사 기준):

| 종류 | 출처 | 커버리지·비고 |
|---|---|---|
| 편의점 | 소상공인시장진흥공단 상가(상권)정보 (공공데이터포털, 분기 갱신, 이용제한 없음) | 전국 약 5.3만 점포, 좌표 포함 |
| 화장실 | 행정안전부 전국공중화장실표준데이터 (5.2만 개소, 개방시간 포함) + OSM 보조 | 2025.2부터 원천에서 좌표 제공 중단 — 개발 단계에서 주소를 일괄 지오코딩(카카오)해 복원 |
| 음수대 | 서울시 공원음수대(주 1회 갱신) + OpenStreetMap `amenity=drinking_water` (ODbL) | 전국 표준데이터 부재 — 서울·한강 위주(OSM 전국 675곳 중 서울 232곳), 지방 공백 큼 |

- **프라이버시**: 코스는 사용자의 위치 이력이다 — 서버로 보내지 않는다. POI 데이터셋을
  앱에 내장하고 매칭은 전부 온디바이스로 한다. (지도 타일 로드는 기존 화면과 동일한 MapKit)
- **미노출 가드 유지**: 코스 주변에 해당 종류 POI가 없으면 억지로 채우지 않고
  "이 코스 주변 급수 정보가 없어요"로 정직하게 안내한다 — 특히 급수대는 서울 밖
  데이터 공백이 크다는 사실을 화면에 명시한다.
- **데이터 신선도**: 번들 데이터는 앱 업데이트 주기로 재생성한다(원본이 분기 갱신).
  화면에 데이터 기준일을 표기한다.

### 4.14 대회 캘린더 — 전국 마라톤 접수 일정 (v0.6 신규, 5번째 탭 "대회")

다음 목표 대회를 찾는 러너에게 전국 마라톤 접수 일정을 보여준다.

- **목록**: 오늘 기준 대회일이 가까운 순. 대회명·종목·지역·장소·접수기간과
  접수 상태 배지(접수중/접수예정/접수완료), 대회 D-day를 표시한다.
  접수 마감일이 지난 대회는 **접수완료**로 남기고, 대회일 자체가 지난 대회는 뺀다.
- **상세**: 종목 칩, 일시(출발 시각 포함), 장소(+대회장 지도), 접수기간, 주최,
  대회 소개 원문, **참가하기** 버튼 → 대회 홈페이지 이동.
- **참가비·기념품**: 출처에 구조화 필드가 없다 — 별도 파싱으로 지어내지 않고,
  대회 소개 원문에 실린 경우만 그대로 노출한다 (미노출 가드).
- 판정·정렬은 RaceEngine(순수 로직, `now` 주입, KST 달력 고정)이 한다.
  접수 시작·마감을 둘 다 모르면 상태 배지를 아예 그리지 않는다.

**데이터 파이프라인** (2026-08 조사 기준):

| 구성 | 내용 |
|---|---|
| 출처 | 로드런(roadrun.co.kr) 대회 일정 — 국내 최다 등록(연 500건+), 상세에 일시·종목·지역·장소·주최·접수기간·홈페이지·좌표가 구조화되어 있다 |
| 배치 | GitHub Actions 매일 05:00 KST — `tools/race-info/crawl.py`가 목록+상세를 크롤링(CP949, 요청 간격 0.6초)해 `ios/RunWrap/Races.json` 갱신. 대회 내용이 바뀐 날만 커밋 |
| 전달 | 앱(RaceStore)이 raw.githubusercontent.com에서 수신. 실패하면 Application Support 캐시 → 앱 번들 사본 순으로 폴백해 오프라인에서도 마지막 자료를 보여준다 |

- 검토 후 접은 대안: 문체부 공공데이터(전국 마라톤 대회 정보)는 18건짜리 1회성
  스냅샷이라 제외. 고러닝(gorunning.kr)은 보조 후보로만 남겨 둔다.
- **네트워크는 수신 전용** — 요청에 어떤 사용자 데이터도 싣지 않는다.
  건강 데이터 반출 없음 원칙(§5 "서버: 없음"의 예외는 날씨와 대회정보 수신뿐)은 유지된다.
- 화면에 자료 출처(로드런)와 갱신 날짜를 표기하고, 최종 확인은 대회 홈페이지
  몫임을 상세 하단에 고지한다.

## 8. MVP 로드맵 (v0.2 개편)

| 11 | 백그라운드+알림 | 운동 감지 → 캐시 → 정시 알림 | 가장 까다로움 | |
| 12 | 수분 섭취 알람 (§4.10) | 예보 온도 조건부 알림 + 끄기 토글 | 1~2일 | 9·11단계 의존 |
| 13 | 런미새 보이스&톤 + 칭호 (§4.11·§4.12) | 노출 문장 전수 리라이트, PhraseBank·TitleEngine + 테스트, 카드 칭호 슬롯 | 2~3일 | v0.4 신규 |
| 14 | 코스 보급 가이드 (§4.13) | GPX 업로드 → 지도+리스트로 km 지점별 급수·화장실·편의점 표시, 매칭 엔진 테스트 통과 | 3~5일 (데이터 파이프라인 포함) | v0.5 신규 |
| 15 | 대회 캘린더 (§4.14) | 크롤링 배치 → 목록·상세·참가하기, 접수 상태 엔진 테스트 통과 | 2~3일 (배치 포함) | v0.6 신규 |

> **게이트 조건 (유지)**: 7단계에서 스스로 "올리고 싶지 않다"고 판단되면 8단계는 진행하지
> 않고 카드 디자인으로 회귀한다. 9단계 이후는 게이트 결과와 무관하게 앱 자체의 유용성을
> 높이는 축이므로 게이트 실패 시에도 진행할 수 있다.
> 13단계(칭호·캡션) 반영 후에는 게이트 판정에 "올리고 싶은가"와 함께 **"웃긴가"** 축을 추가한다.
