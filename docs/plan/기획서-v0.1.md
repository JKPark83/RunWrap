# 러너 리포트 앱 기획서 (초안)

> **버전**: v0.1 (초안)
> **작성일**: 2026-08-11
> **상태**: 컨셉 검증 전 — MVP 1~3단계 완료 후 v0.2로 갱신 예정

---

## 1. 한 줄 정의

애플워치에 쌓인 러닝 데이터를 **러너에게 의미 있는 지표로 재가공**해 주기적으로 알려주고, 탭 한 번으로 **인스타그램에 올릴 수 있는 카드 이미지**를 만들어주는 아이폰 전용 앱.

---

## 2. 배경 및 문제 정의

### 2.1 기존 도구의 공백

- 애플 기본 건강/피트니스 앱은 **원시 데이터 나열**에 가깝다. "이번 주 부하가 위험 수준인가", "컨디션이 오르고 있는가" 같은 질문에 답하지 않는다.
- 러너가 SNS에 기록을 공유하려면 스크린샷 → 편집 앱 → 인스타그램의 3단계를 매번 반복해야 한다.
- 서버 기반 자동 게시는 Instagram Graph API의 제약(프로페셔널 계정, Facebook 페이지 연동, Meta 앱 심사 2~4주)과 HealthKit의 구조적 제약(클라우드 API 부재, 잠금 시 접근 불가)으로 개인이 운영하기에 비용 대비 효율이 낮다.

### 2.2 설계 원칙

1. **온디바이스 우선** — 서버 없이 기기에서 읽고, 계산하고, 렌더링한다.
2. **자동 게시가 아닌 원탭 공유** — 사용자 탭이 개입하므로 Meta 심사 파이프라인을 완전히 우회한다.
3. **알림은 정확하게, 계산은 미리** — iOS 백그라운드 실행의 불확실성을 알림/계산 분리로 흡수한다.

## 4. 핵심 기능

### 4.1 건강 데이터 수집 (HealthKit)

- `HKWorkoutType` 러닝 세션: 거리, 시간, 페이스, 칼로리
- `HKQuantityType`: 심박, 케이던스, 파워(지원 기기), 걸음 수
- `HKWorkoutRoute`: GPS 경로 (지도 카드 렌더링용)
- 읽기 전용 권한만 요청. 쓰기 권한 불필요.

### 4.2 러너 특화 리포트 (차별화 핵심)

기본 앱이 보여주지 않는 **파생 지표**를 계산한다:

| 지표 | 의미 | 알림 예시 |
|---|---|---|
| 주간 거리 증가율 | 10% 룰 위반 감지 | "지난주 대비 +23% — 과부하 구간입니다" |
| ACWR (급성:만성 부하비) | 부상 위험 지표 | "이번 주 부하가 4주 평균의 1.6배입니다" |
| 심장 드리프트 | 같은 페이스 대비 심박 추이 = 컨디션 프록시 | "동일 페이스 심박이 3주째 하락 중 — 체력이 오르고 있습니다" |
| 케이던스/보폭 추이 | 러닝 폼 변화 | "케이던스가 평균 대비 5% 낮았습니다" |

> **원칙**: "오늘 5km 뛰었습니다"는 아무도 열지 않는다. 알림은 반드시 **해석된 인사이트**를 담는다.

### 4.3 주기적 알림

- 사용자가 리포트 주기 설정: 매일 / 매주 / 운동 직후
- `UNCalendarNotificationTrigger`로 알림 시각은 정확하게 보장
- 리포트 본문은 사전 계산·캐시, 앱 진입 시 최신 데이터로 갱신

### 4.4 인스타그램 공유 카드

- "공유하기" 탭 → 9:16 세로 카드 이미지 생성 (SwiftUI `ImageRenderer`)
- 카드 구성: 날짜, 거리, 페이스, 심박 존, 경로 지도(MapKit 스냅샷), 주간 요약
- `instagram-stories://` URL 스킴으로 **인스타그램 스토리 편집 화면에 즉시 진입**
- 폴백: 인스타그램 미설치 시 공유 시트(`UIActivityViewController`) / 사진 앱 저장

## 5. 기술 아키텍처

```
[애플워치] ──(자동 동기화)──> [iPhone HealthKit 저장소]
                                      │
                              HKObserverQuery
                              (+ enableBackgroundDelivery)
                                      │ 새 운동 감지 시 앱 웨이크업
                                      ▼
                            [리포트 엔진 (온디바이스)]
                             ├─ 파생 지표 계산
                             ├─ 로컬 캐시 (SwiftData/CoreData)
                             └─ 알림 예약 (UNCalendarNotificationTrigger)
                                      │
                        사용자 알림 탭 → 앱 진입
                                      ▼
                            [리포트 화면 (SwiftUI)]
                                      │ "공유하기"
                                      ▼
                            [ImageRenderer → 9:16 카드]
                                      │
                            instagram-stories:// URL 스킴
                                      ▼
                            [인스타그램 스토리 편집 화면]
```

**서버: 없음.** 모든 계산·렌더링은 온디바이스. 운영비 0원, 개인정보 외부 전송 없음.

### 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| UI | SwiftUI | iOS 17+ 타겟 |
| 데이터 | HealthKit (읽기 전용) | |
| 저장 | SwiftData | 리포트 캐시, 설정 |
| 백그라운드 | HKObserverQuery + BGAppRefreshTask | 실행 시점 보장 없음을 전제로 설계 |
| 알림 | UserNotifications | 시각 보장은 이쪽 |
| 이미지 | ImageRenderer + MapKit 스냅샷 | |
| 공유 | instagram-stories:// (IGStoryKit 검토) | Info.plist LSApplicationQueriesSchemes 등록 |

## 6. 알려진 제약과 대응

| 제약 | 내용 | 대응 |
|---|---|---|
| 잠금 시 HealthKit 접근 불가 | 애플 정책, 우회 불가 | 잠금 해제 시점에 계산 — 일일 리포트 특성상 실질 영향 작음 |
| 백그라운드 실행 비보장 | BGTask는 기회주의적 실행 | 알림(정확)과 계산(사전 캐시) 분리 |
| HKObserverQuery 빈도 제한 | 타입별 상이 | 운동 타입은 즉시성 양호 — 운동 감지를 주 트리거로 |
| 인스타 피드 자동 게시 불가 | 개인 계정 API 제외 | 스토리 원탭 공유로 대체 (의도된 설계) |
| App Store 심사 | HealthKit 앱 요건 | 개인정보처리방침, NSHealthShareUsageDescription 명시, 건강 데이터 광고 활용 금지 준수 |

## 7. 경쟁 및 차별화

**주요 경쟁**: Strava, HealthFit, Athlytic, Runna, Training Today

| 축 | 경쟁 상황 | 본 앱의 포지션 |
|---|---|---|
| 고급 지표 | HealthFit·Athlytic이 강함 | 지표 나열이 아닌 **한국어 인사이트 문장** 중심 |
| 공유 카드 | Strava가 잘 만듦 | 알림 → 카드 → 스토리까지 **탭 2번** 흐름의 마찰 최소화 |
| 가격 | 대부분 구독제 | 미정 (MVP 검증 후 결정) |

> 차별화 가설: "지표를 보여주는 앱"이 아니라 **"오늘 뭘 알아야 하는지 문장으로 말해주고, 자랑은 탭 한 번에 끝내주는 앱"**. 이 가설은 MVP 3단계에서 검증한다.

---

## 8. MVP 로드맵

검증 우선순위 순서. **각 단계는 다음 단계의 게이트다.**

| 단계 | 내용 | 완료 기준 | 예상 규모 |
|---|---|---|---|
| 1 | HealthKit 연결 | 권한 요청 → 최근 러닝 목록 표시 | 반나절 |
| 2 | 리포트 엔진 | 파생 지표 2~3개 계산, 본인 데이터로 유용성 자가 검증 | 수일 |
| 3 | 카드 생성 | ImageRenderer → 사진 저장. **"내가 올리고 싶은 퀄리티인가?"** | 수일 |
| 4 | 인스타 연동 | instagram-stories:// 스토리 진입 | 수 시간 |
| 5 | 백그라운드+알림 | 운동 감지 → 캐시 → 정시 알림 | 가장 까다로움, 마지막 |

> **게이트 조건**: 3단계에서 스스로 "올리고 싶지 않다"고 판단되면 4·5단계는 진행하지 않고 카드 디자인으로 회귀한다.

|---|---|---|---|
